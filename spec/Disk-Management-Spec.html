01全体像と現状

本ツールは Disk-Management.bat をダブルクリックすることで開始し、管理者権限が無ければ UAC で自動昇格したうえで Disk-Management.ps1 を -ExecutionPolicy Bypass で実行する。処理は3つの Phase から成る。

PHASE 1

導通確認・容量取得

対象9台に ping と WMI/WinRM で接続し、ドライブ毎の空き容量・全容量を取得する。実装済み・稼働実績あり。

PHASE 2

運用日誌への転記

共有フォルダ上の Excel ブックをコピーし、MENU シートの日付と容量シートの数値を更新して保存する。本仕様書で新規に定義。

PHASE 3

結果HTMLレポート

Phase 1・2 双方の結果を1枚のHTMLにまとめ、ルートフォルダ直下に保存する。出力先・命名は既存仕様を継続、内容をPhase 2の結果まで拡張。

現状の実装範囲

Phase 1 相当（導通確認・容量取得・簡易HTMLレポート）は既に Disk-Management.ps1 として実装され、直近の実行結果 Disk-Management-202608241335.HTML が存在する。本仕様書は、これに Phase 2（Excel転記）を追加するための仕様を定める。

04Phase 1: 導通確認・容量取得実装済み

既存 Disk-Management.ps1 がそのまま担う部分。変更は無く、Phase 2 の入力データとして利用する。

4.1 導通確認

  • 対象への ping を規定回数（既定2回）実施し、1回でも応答があれば「導通OK」とする。
  • 導通NGでも、WMI/WinRM 経由で容量取得を試行する（ping はブロックされるがWMIは通る環境があるため）。

4.2 容量取得

  • 1次経路: Get-WmiObject（DCOM, PacketPrivacy 認証）で Win32_LogicalDisk を取得。
  • 2次経路: WinRM (CIM/WSMan) へフォールバック。ただし認証エラー時はフォールバックしない（ロックアウト防止）。
  • 値は GB（1GB = 10243 バイト、エクスプローラー表示と同基準）、小数点以下2桁で表記する。
  • 使用率 80% 以上を「警告」、90% 以上を「危険」と判定する。

05Phase 2: Excel運用日誌への転記新規

対象共有フォルダ上の日次 Excel ブックを前日ファイルからコピーして当日ファイルを作成し、日付と容量データを更新して保存する。

5.1 対象フォルダの特定

\\gmsv0002\006情シスs\04.共通管理\00.システム運用日誌\{YYYY}年度\{YYYYMM}

{YYYY}年度・{YYYYMM} は実行日時点の年度・年月フォルダ（常に最新の月フォルダ）を指す。年度の切り替わり（決算期）ルールは既存フォルダ命名慣行に従う。

5.2 前日ファイルの存在確認

システム運用日誌_{YYYYMMDD}.xlsm （{YYYYMMDD} は実行日の前日日付）

上記フォルダ内に前日ファイルが存在することを確認する。存在しない場合は Phase 2 を中断し、BLOCKED として Phase 3 のレポートに記録する。

5.3 当日ファイルの作成

前日ファイルをコピーし、当日日付のファイル名にリネームして同フォルダに保存する（コピー元は前日ファイルそのものであり、シート「サーバー管理日誌(統合)」を含むブック全体を複製する）。

5.4 シート「MENU」の更新

セル内容処理
D10日付（実行日の前日）前日日付になっているか確認。ずれていれば MM/DD 形式で前日日付に修正する。
E10データ当日の日付D10 の修正が正しく反映されたことを確認したうえで、データ当日（実行日）の日付になっているか確認する。

5.5 シート「サーバー管理日誌(統合)」の更新

列処理
容量（全容量）既存値を確認する（通常は変化しない想定。実測値と差異があれば警告として記録し、値そのものは上書きしない）。
空き（空き容量）既存データを削除し、Phase 1 で取得した最新の空き容量を入力する。

各機器・各ドライブと、シート上の行／列の対応関係は現物ブックのレイアウトに基づく。実装前に現物ファイルで確定する必要がある（9章 要確認事項 4番）。

5.6 保存

更新後、当日ファイルを上書き保存して Excel を終了する。前日ファイルは削除せずそのまま残す。

07実行環境・前提条件

  • 起動: Disk-Management.bat を管理者権限で実行（未昇格なら UAC で自動昇格）。
  • 本体: Disk-Management.ps1 を Windows PowerShell 5.1、-ExecutionPolicy Bypass で実行。コメント等は英語表記可。
  • Excel操作: 実行端末にインストール済みの Microsoft Excel を COM オートメーション（Excel.Application）で操作する前提。
  • ネットワーク: 対象9台への RPC(WMI)／WinRM 到達性に加え、\\gmsv0002\006情シスs\... 共有フォルダへの読み書き権限が必要。
  • 資格情報の保管: 認証情報はスクリプト内に平文で保持するため、フォルダのアクセス権限を運用担当者に限定する（既存方針を継続）。

08エラーハンドリング方針

状態条件対応
導通NGping 応答なし容量取得は継続して試行し、結果を記録する。
認証エラーアクセス拒否／パスワード誤り／ロックアウト別経路(WinRM)への再試行を行わない。ロックアウト防止を最優先する。
取得失敗上記以外の通信・WMIエラーエラー内容を備考に記録する。
ドライブ未検出対象ドライブレターが存在しない「ドライブ未検出」として記録する。
BLOCKED (Phase2)共有フォルダに前日ファイルが存在しないPhase 2 を中断し BLOCKED として記録。Phase 1 の結果は通常通り出力する。
FAIL (Phase2)Excel 保存失敗（ファイルロック中・排他制御など）再試行後、失敗時は FAIL として記録し、後続機器の記録・Phase 3 出力は継続する。

09要確認事項

以下は指示内容だけでは一意に確定できない、または現物確認が必要な点。実装着手前にユーザーへ確認する。

Q1アカウント名の表記
指示原文は adminstrator（i 抜け）だが、既存 Disk-Management.ps1 の実績あるアカウント名は正しいスペルの administrator。意図的な別アカウント名か、入力上のタイプミスか。特段の指定がなければ実績のある administrator を採用する想定。
Q2MAGNET側ユーザー名 1\administrator の意味
先頭の 1 がドメイン名／コンピューター名として妥当か。ローカルアカウントを指す場合、通常は対象機器のコンピューター名または .（ローカルを表す記号）を使う。
Q3「サーバー管理日誌(統合)をコピペして最新ファイル名とする」の対象
本仕様書は「前日ファイル（システム運用日誌_YYYYMMDD.xlsm）自体をコピーし、当日日付にリネームする」と解釈した。別途「サーバー管理日誌(統合).xlsm」という名前の専用テンプレートファイルが存在する場合は手順を差し替える必要がある。
Q4シート「サーバー管理日誌(統合)」の実セルレイアウト
機器名・ドライブ・容量・空き容量が、シート上のどの行／列に対応するかは現物ブックが手元にないため未確定。実装前に現物ファイルでレイアウトを確認する必要がある。
Q5「容量（全容量）」列の扱い
「確認したうえで入力」という指示のため、本仕様書では既存値の確認のみ（上書きしない）とした。実測値と食い違った場合に上書きすべきかどうかを確認したい。
Q6前日ファイルの扱い
当日ファイル作成後、前日ファイルは削除せずそのまま残す想定でよいか。
Q7実行端末の Excel 有無
Phase 2 は Excel の COM オートメーションを前提とする。本スクリプトを実行する端末に Microsoft Excel がインストールされている前提でよいか。
